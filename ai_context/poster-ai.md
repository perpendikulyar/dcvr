## 1. Problem statement (Проблема)

В одной выгрузке около 3 000 публикаций. Вручную найти в ней темы, которые зайдут нашей аудитории,
увидеть связи между ними и придумать, о чём писать, долго и субъективно.

## 2. Vision / Why (Зачем)

Кнопка «Проанализировать» на выгрузке. Через несколько минут появляются **10–20 трендовых тем** под
аудиторию с метриками, объяснением «почему это в тренде», связями между темами и готовыми идеями
контента для UGC-формата.

## 3. Audience (Для кого контент)

UGC-сервис с преимущественно женской аудиторией (Россия). Тематики: отношения, быт, дом,
садоводство, рецепты, жизненные ситуации, культурные события.

**Исключаем:** политику, знаменитостей, спортивные новости (матчи, клубы, турниры).

### 3.1 Интересы аудитории (DMP)

Интересы определены DMP-системой и упорядочены **от большего к меньшему**. Ранг задаёт вес интереса
при оценке тем:

| # | Интерес | # | Интерес | # | Интерес |
|---|---|---|---|---|---|
| 1 | Отношения | 11 | Красота и здоровье | 21 | Кулинария |
| 2 | Развлечения и досуг | 12 | Уход за волосами и телом | 22 | Чай |
| 3 | Кино | 13 | Медицинские товары | 23 | Техника для красоты и здоровья |
| 4 | Рестораны | 14 | Здоровое питание | 24 | Техника для дома |
| 5 | Книги | 15 | Косметика | 25 | Товары для детей |
| 6 | Музыка | 16 | Фитнес | 26 | Отдых и путешествия |
| 7 | Декор | 17 | Йога | 27 | Отели |
| 8 | Игры | 18 | Спортивные товары | 28 | Спортивный туризм |
| 9 | Телевидение | 19 | Одежда и обувь | 29 | Подарки и цветы |
| 10 | Танцы | 20 | Кредиты, ипотека | 30 | Животные |

- Список хранится в конфиге (`server/src/ai/audience.ts`) и редактируется без изменения кода пайплайна.
- **Вес интереса:** `weight = 1 − (rank − 1) / N`, то есть от 1.0 у «Отношений» до ~0.03 у «Животных».
  Формулу можно заменить реальными долями аудитории из DMP, если они появятся.
- **Спорт:** исключаются спортивные *новости*. Активный образ жизни (фитнес, йога, спорттовары,
  спортивный туризм) остаётся, это интересы аудитории.
- **Финансы:** «Кредиты, ипотека» есть в интересах, поэтому категории `/Finance` и `/Real Estate`
  не исключаются.

## 4. Scope (Что делаем)

### 4.1 Пайплайн анализа одной выгрузки

| # | Шаг | Исполнитель | Что получаем |
|---|---|---|---|
| 1 | **Пре-фильтр** | Код | Исключённые категории (см. 4.2) отбрасываются, строки без категории остаются |
| 2 | **Map: разметка** | LLM, батчи по ~80 строк | Для каждой строки: `relevant` (да/нет), короткий ярлык темы, **0–3 интереса DMP** из списка 3.1 (только из списка, по id) |
| 3 | **Reduce: темы** | LLM, 2 прохода | Ярлыки почти уникальны (в примере 871 ярлык на 994 публикации), поэтому модель возвращает **только группы для объединения**: сначала внутри чанков по 150 ярлыков, упорядоченных по интересу, затем между чанками. Если второй проход не удался, остаются результаты первого |
| 4 | **Метрики и скоринг** | Код | По каждой теме: Σ Impressions, число публикаций и издателей, распределение по интересам, **Audience score** (см. ниже), топ-публикации |
| 5 | **Синтез** | LLM (сильная модель) | Для топ-N тем по Audience score: название, «почему в тренде», каким интересам отвечает и почему, связи с другими темами, 3–5 идей (заголовок, формат, угол, хук для вовлечения), где возможно на **пересечении интересов** (например, «Отношения × Рестораны»: идеи для свиданий) |

Все числа считает код, LLM получает их готовыми. Ответы LLM проверяются по zod-схеме; при
невалидном JSON запрос повторяется.

**Audience score темы** (считает код):

```
interestWeight = max(weight(i)) по интересам темы, + бонус 0.1 за каждый дополнительный интерес
reach          = log10(Σ Impressions) нормированный к [0, 1] по всем темам выгрузки
score          = 0.6 × interestWeight + 0.4 × reach
```

Темы без единого интереса DMP в топ не попадают. Коэффициенты вынесены в конфиг и подбираются по
результатам первых прогонов.

### 4.2 Пре-фильтр (по данным примера)

Исключаем категории (с подкатегориями): `/Sports`, `/News/Politics`, `/Law & Government`,
`/Arts & Entertainment/Celebrities & Entertainment News`. В примере это ~640 строк.
`/News/Weather` (85 строк) **оставляем**: погода влияет на быт, дачу и рецепты.
Список настраивается в конфиге. Политику и знаменитостей, которые попали в другие категории или в
строки без категории, отсекает шаг 2 (`relevant = false`).

### 4.3 UI

- Вкладка **«Инсайты»** у выгрузки: кнопка «Проанализировать», прогресс по шагам, выбор провайдера.
- Карточки тем: название, метрики, Audience score, бейджи интересов DMP, «почему в тренде»,
  идеи контента (с копированием).
- Фильтр карточек по интересам DMP и сводка «сколько тем и показов на каждый интерес», чтобы было
  видно, какие интересы в этой выгрузке не покрыты трендами.
- Блок «Связи между темами».
- Клик по теме открывает таблицу, отфильтрованную по публикациям этой темы.
- Результаты сохраняются в БД; повторный просмотр не тратит запросы, перезапуск только явный.

### 4.4 Non-goals (в этом этапе не делаем)

- Динамику по нескольким выгрузкам («растущие / новые» темы): следующий спринт.
- Генерацию готовых текстов статей: только идеи и заголовки.
- Few-shot на примерах успешного контента: примеров пока нет, добавим позже.

## 5. How (Решение)

### 5.1 LLM-провайдеры

Один адаптер `LlmProvider` поверх **OpenAI-совместимого Chat Completions API**, провайдер выбирается в `.env`.

| Провайдер | Роль | Плюсы | Минусы |
|---|---|---|---|
| ~~**Vireonix**~~ | **Отказались** 2026-10-29 | Бесплатно, без ключа | На реальном прогоне ответил: *«Automated bulk tasks detected. Future requests will be blocked due to the TOS violation»*; правила запрещают пакетную обработку. До этого: ~60% ответов 502, ~100 с на батч, обрезанный JSON на длинных ответах |
| **YandexGPT** (Yandex AI Studio) | **Основной** (по умолчанию) | Сильный русский; работает из РФ; есть OpenAI-совместимый эндпоинт и эмбеддинги | Платно (но дёшево, см. 5.2); нужен аккаунт Yandex Cloud, folder ID, API-ключ |

Данные — публичная статистика публикаций, поэтому чувствительность низкая и отправлять их во
внешний сервис для эксперимента допустимо.

### 5.2 Оценка стоимости YandexGPT за один прогон

Тарифы с [официальной страницы](https://aistudio.yandex.ru/docs/en/ai-studio/pricing), без НДС, синхронный режим:

| Шаг | Модель | Токены | Цена за 1K | Итого |
|---|---|---|---|---|
| Map (~2 300 строк после фильтра) | YandexGPT Lite | ~250K | $0.0016 | ~$0.40 |
| Reduce + синтез | YandexGPT Pro 5.1 | ~40K | $0.0066 | ~$0.26 |
| **Итого** | | | | **< $1 (~50–80 ₽)** |

### 5.3 Надёжность

- Ретраи с экспоненциальной паузой на 429/5xx (обязательно для Vireonix).
- Батчи обрабатываются параллельно с ограничением (2–3 одновременно), промежуточные результаты
  сохраняются, так что упавший прогон продолжается с места падения.
- Анализ выполняется фоновой задачей; UI опрашивает статус.

### 5.4 Модель данных

```sql
ai_runs(id, upload_id, provider, model, status, step, error, created_at, finished_at)
ai_item_labels(run_id, publication_id, relevant, label, interests_json)
ai_topics(id, run_id, title, why_trending, interests_json, interests_reason, audience_score,
          impressions, publications, publishers, ideas_json, related_json)
ai_topic_items(topic_id, publication_id)
```

## 7. Success metrics (Критерии успеха)

- Прогон на файле-примере завершается без ручного вмешательства (с учётом ретраев).
- Из выдачи ≥ 60% тем вы оцениваете как «подходит аудитории».
- Ни одной темы про политику, знаменитостей или спортивные новости в топе.
- Каждая тема в топе привязана хотя бы к одному интересу DMP, а топ-10 интересов представлены в
  выдаче, если в выгрузке есть подходящие публикации.
- Каждая тема ведёт к реальным публикациям из выгрузки.

## 8. Risks (Риски)

| Риск | Митигация |
|---|---|
| Провайдер недоступен или нестабилен | Ретраи; продолжение прерванного анализа; смена провайдера одной строкой в `.env` |
| Длинный ответ модели обрезается | Reduce возвращает только группы; упавший чанк делится пополам и повторяется |
| LLM «галлюцинирует» темы или цифры | Цифры считает код; каждая тема привязана к id публикаций |
| Невалидный JSON от моделей | zod-схема, повтор с текстом ошибки |
| LLM придумывает интересы вне списка DMP | Модель выбирает интересы по id из списка; zod отклоняет неизвестные id |
| Ранг ≠ реальная доля аудитории | Вес вынесен в конфиг; при наличии долей из DMP подставляем их |
| Качество `auto`-роутинга Vireonix плавает | Фиксируем модель в `ai_runs`; эталонная модель — YandexGPT |
