# Project Poster: Discover Stats Viewer (dcvr)

> Формат: Atlassian Project Poster · Статус: **MVP готов (этапы 0–4)** · Дата: 2026-10-28

---

## 1. Problem statement (Проблема)

Выгрузки статистики публикаций (Discover, CSV — 15 колонок, ~3 000 строк в одном файле) неудобно смотреть
в табличном редакторе:

- нельзя быстро отфильтровать по издателю и по иерархической категории (`/Sports/Team Sports/Soccer`);
- много шума: колонки, которые не нужны для отбора материалов;
- нет истории: каждая выгрузка живёт отдельным файлом, сравнить или вернуться к старой неудобно;
- отбор подходящих материалов делается вручную; в будущем его нужно автоматизировать с помощью ИИ.

## 2. Vision / Why (Зачем)

Внутренний веб-сервис: загружаешь CSV, получаешь удобную таблицу с фильтрами по Publisher и Category
(с учётом вложенности), сортировкой по Impressions и переходом к источнику в один клик.
Данные сохраняются в БД, чтобы на следующем этапе подключить ИИ-анализ и отбор материалов.

## 3. Value (Ценность)

| Для кого | Ценность |
|---|---|
| Редактор / аналитик | Находит релевантные материалы за минуты, а не за часы ручной фильтрации |
| Команда | Единое место с историей выгрузок |
| Следующий этап (ИИ) | Готовая структурированная база для анализа и скоринга материалов |

## 5. Scope (Что делаем)

### 5.1 Входные данные

CSV-файл (пример: `stat_files/discover-publications-20261028-1149.xlsx - Publications.csv`).

Колонки файла: `Title, Publisher, Category, Entity, Type, Format, Impressions, Average position,
First seen, Last seen, Published, Source URL, Summary, Image URL, Characters`.

Что видно в примере:
- 2 962 строки, 758 уникальных Publisher (домены, вложенности нет);
- 283 уникальные Category, иерархия через `/`, глубина до 3 уровней, 608 строк без категории;
- `Average position` в формате с запятой (`"5,38"`); Summary пустой у ~14% строк;
- Title и Summary содержат запятые и кавычки, поэтому нужен корректный CSV-парсер (RFC 4180).

### 5.2 Отображаемые колонки

| Колонка | Отображение |
|---|---|
| Title | Текст |
| Publisher | Текст (домен) |
| Category | Путь категории (breadcrumbs) |
| Entity | Текст |
| Source URL | Иконка ↗, открывает ссылку в новой вкладке |
| Summary | Сокращённый текст, полный по раскрытию/hover |
| Impressions | Число с разделителями разрядов, сортировка (по умолчанию DESC) |

Остальные колонки **сохраняются в БД** (пригодятся для ИИ), но в UI не выводятся.

### 5.3 Функциональность MVP

1. **Загрузка CSV** (drag & drop / выбор файла) → парсинг → сохранение в SQLite как отдельная «загрузка».
2. **Список загрузок**: имя файла, дата, количество строк; выбор активной; удаление.
3. **Таблица публикаций** с серверной пагинацией и сортировкой (Impressions, Title, Publisher).
4. **Фильтр Publisher:** плоский мультиселект с поиском и счётчиками строк.
5. **Фильтр Category:** дерево с чекбоксами по сегментам `/`.
   Выбор родителя включает всех потомков (`/Sports` → `/Sports/Team Sports/Soccer` и т.д.).
   Отдельный пункт «Без категории».
6. Счётчики в фильтрах и итоговое количество найденных строк.
7. Состояние фильтров хранится в URL (можно поделиться ссылкой).

### 5.4 Non-goals (Не делаем в MVP)

- Авторизация и мультипользовательность (сервис запускается локально).
- Иерархия Publisher (домены остаются плоским списком).
- Слияние и дедупликация между разными выгрузками.
- Импорт XLSX (только CSV).
- ИИ-анализ: следующий этап, в MVP только подготовка под него.

## 6. How (Решение)

### 6.1 Стек

| Слой | Технологии |
|---|---|
| Монорепо | npm workspaces: `server/`, `web/`, `shared/` (общие TS-типы) |
| Backend | Node.js 22.13+, TypeScript 6, Fastify 5, `@fastify/multipart`, `csv-parse` |
| БД | SQLite (встроенный `node:sqlite`), миграции в `server/src/db/migrations.ts` |
| Валидация | `zod` (строки CSV, query-параметры API) |
| Frontend | React 18, Vite 8, TypeScript, TanStack Table v8, TanStack Query v5 |
| Качество | ESLint, Prettier, Vitest |

### 6.2 Модель данных

```sql
uploads(
  id INTEGER PK, filename TEXT, uploaded_at TEXT, row_count INTEGER
)

publications(
  id INTEGER PK, upload_id INTEGER FK → uploads ON DELETE CASCADE,
  title TEXT, publisher TEXT, category TEXT, entity TEXT,
  type TEXT, format TEXT, impressions INTEGER, avg_position REAL,
  first_seen TEXT, last_seen TEXT, published TEXT,
  source_url TEXT, summary TEXT, image_url TEXT, characters INTEGER
)
-- индексы: (upload_id, impressions), (upload_id, publisher), (upload_id, category)
```

Фильтр по категории с учётом вложенности: `category = :c OR category LIKE :c || '/%'`.

### 6.3 API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/uploads` | Загрузка CSV (multipart) → `{ uploadId, rowCount }` |
| GET | `/api/uploads` | Список загрузок |
| DELETE | `/api/uploads/:id` | Удаление загрузки |
| GET | `/api/uploads/:id/publications` | `?publisher[]=&category[]=&sort=&order=&page=&pageSize=` |
| GET | `/api/uploads/:id/facets` | Publisher со счётчиками и дерево Category со счётчиками |

### 6.4 Задел под ИИ (этап 2)

- Провайдер ИИ **пока не выбран**, поэтому закладываем интерфейс `LlmProvider` (`analyze(items, criteria)`), реализацию выберем позже.
- Отдельная таблица `ai_assessments(publication_id, score, verdict, reason, model, created_at)`, исходные данные не меняются.
- Все исходные колонки (Type, Format, Entity, Summary, Characters) уже в БД, их можно передавать в промпт.

- Файл-пример (~3,3 МБ, 2 962 строки) импортируется меньше чем за 3 секунды.
- Применение фильтра в UI занимает меньше 300 мс.

- Все 7 колонок отображаются корректно, Source URL открывается в новой вкладке.

## 9. Risks & Assumptions (Риски и допущения)

| Риск / допущение | Митигация |
|---|---|
| Формат выгрузки может меняться (колонки, порядок) | Маппинг по имени заголовка, валидация обязательных колонок |
| Числа в локализованном формате (`"5,38"`) | Явная нормализация в парсере |
| Регистр `Type` неоднородный (`News` / `news`) | Хранить как есть; при необходимости нормализовать на этапе ИИ |
| Большие файлы (десятки тысяч строк) | Потоковый парсинг, батчевые вставки, серверная пагинация |
| Провайдер ИИ не выбран | Абстракция `LlmProvider`, данные готовы заранее |
